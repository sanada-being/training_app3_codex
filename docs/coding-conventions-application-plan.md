# コーディング規約適用計画（Issue #78）

## 1. 目的
- `CODING_CONVENTIONS.md` を既存コードへ安全に適用するため、適用方針・例外基準・実行順を固定する。
- 規約適用で挙動変更を起こさないよう、リファクタリング範囲を明確にする。

## 2. 対象スコープ
- 対象レイヤ
  - WinFormsアプリ: `Sales Management App/Sales Management App`（`.cs` 36件）
  - Core: `src`（`.cs` 25件）
  - Tests: `tests`（`.cs` 18件）
- 除外
  - 自動生成コード（例: `*.Designer.cs`, `AssemblyInfo.cs`）
  - 仕様/外部I/F互換に影響する公開契約の変更

## 3. 規約適用マトリクス

| 規約 | 適用判定 | 方針 | 備考 |
|---|---|---|---|
| ファイル名とクラス名一致 | 必須 | 既存コードを一致させる | 自動生成ファイルは除外 |
| クラス接尾辞（`Form`/`View`/`Grid`等） | 段階適用 | 新規コードを優先、既存は影響大のものを計画的に修正 | `Controller` 命名は現構成を優先し例外扱い |
| 接頭辞（`F`/`v`/`w`/`C_`） | 段階適用 | 既存一括リネームは実施しない。新規・局所修正時に適用 | 変更ノイズと回帰リスクを抑制 |
| 関数命名（PascalCase、動詞+名詞） | 必須 | 曖昧命名・不適切命名を修正 | `bool` 判定は `Is/Has/Can/Exists` を適用 |
| 省略語・不自然な単語 | 必須 | 可読性を損なう命名を修正 | 互換性に影響する公開APIは例外判定 |
| 代入/演算子スペース | 必須 | 規約どおり整形 | 自動整形と手動確認を併用 |
| using順序 | 必須 | .NET標準 -> サードパーティ、各グループ内アルファベット順 | ファイル単位で統一 |
| ネスト抑制（早期return） | 推奨（高） | 複雑度の高い箇所から適用 | 挙動不変を前提 |
| 文字列連結（StringBuilder） | 推奨 | ループ内連結・可変長連結を対象に改善 | 固定メッセージ連結は対象外 |
| 公開メンバーXMLコメント | 必須 | `public/protected` に `summary/param/returns` 付与 | 自動生成コードは除外 |
| 履歴コメント禁止 | 必須 | 「誰がいつ」系コメントを削除 | 理由コメントは維持/補強 |
| テストメソッド日本語 | 例外（現時点） | 既存テスト命名は維持、追加方針は別途合意 | 既存資産との一貫性を優先 |

## 4. レイヤ別ギャップ概要
- WinForms/UI
  - 命名規約と可読性規約の未統一が混在
  - `using` 順序と早期return適用の改善余地あり
- Core
  - 全体的に整っているが、命名/コメントの局所差分を確認対象とする
- Tests
  - 既存命名（英語）を維持し、今回スコープは可読性と規約逸脱管理を優先

## 5. 実行順（依存関係）
1. #78 方針確定（本Issue）
2. #79 命名規約適用（識別子/ファイル名）
3. #80 書式・using・可読性統一
4. #81 コメント規約適用
5. #82 回帰確認と逸脱管理

## 6. 規約逸脱の記録ルール
- 規約に反する変更を残す場合、PRに以下を必ず記載する。
  - 対象規約
  - 逸脱対象（ファイル/識別子）
  - 逸脱理由
  - 代替対応
  - 将来の解消方針

記載テンプレート:

```md
- 対象規約:
- 逸脱対象:
- 理由:
- 根拠:
- 将来対応:
```
