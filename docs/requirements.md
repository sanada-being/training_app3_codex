# 要件定義書（販売管理アプリ）

## 1. 目的
- 本部店舗管理部が、商品・在庫・売上を一元管理できること。
- 週次業務（CSV取込、売上確認、在庫確認、集計）を、属人化せず再現できること。
- 入力ミスや操作ミスによるデータ欠損を防ぎ、継続運用できること。

## 2. 商品管理要件
### 要件
- 商品は一意の商品IDで管理する。
- 商品は「商品名」「単価」「区分」を保持する。
- 商品情報の登録・編集・削除・一覧表示ができる。
- 必須項目未入力時は保存できない。
- 単価は0以上の整数であること。

### 受け入れ条件
- 未登録の商品IDで登録すると一覧に追加される。
- 既存の商品IDで登録するとエラー表示される。
- 商品名未入力、単価未入力、区分未入力は保存不可。
- 単価が負数の場合は保存不可。

## 3. 在庫管理要件
### 要件
- 在庫は「店舗ID + 商品ID」単位で管理する。
- 入荷（在庫加算）と出庫（在庫減算）ができる。
- 在庫数は0未満にできない。
- 在庫一覧表示ができる。
- 在庫数が5以下の明細を「要発注」として判定できる。

### 受け入れ条件
- 入荷数量入力後に在庫が増加する。
- 出庫時、在庫不足なら処理を中止してエラー表示する。
- 在庫が5以下の明細が要発注一覧に表示される。

## 4. 売上管理要件
### 要件
- 売上は「販売日」「店舗ID」「商品ID」「数量」を保持する。
- 売上登録時に売上金額（単価×数量）を算出する。
- 売上登録時に在庫を同時に減算する。
- 在庫不足時は売上登録を中止する。
- 売上一覧を表示できる。

### 受け入れ条件
- 有効な商品ID・数量で登録すると売上履歴に追加される。
- 売上金額が単価×数量で計算される。
- 在庫不足時は売上登録されず、在庫も変更されない。

## 5. 売上集計要件
### 要件
- 期間指定（開始日〜終了日）で売上を集計できる。
- 商品別の売上金額を算出できる。
- 商品別の販売数量を算出できる。
- 期間合計（週次合計）を算出できる。

### 受け入れ条件
- 指定期間の売上のみを対象に集計される。
- 手計算結果と集計結果が一致する。
- 商品別の数量/金額を画面で確認できる。

## 6. データ管理要件
### 要件
- `products.csv` / `inventory.csv` / `sales_yyyyMMdd.csv` の読込ができる。
- 業務更新後データをCSVとして保存できる。
- ファイル不在・形式不正・必須欠落時にエラー内容を表示できる。
- 破壊的更新前にバックアップを作成できる。

### 受け入れ条件
- 正常CSVを読込でき、画面に反映される。
- 不正CSVは読込中止され、原因が通知される。
- 保存前バックアップが作成される。

## 7. 操作性・信頼性要件
### 要件
- 長時間処理（CSV読込・集計）でUIが固まらないこと。
- 重要操作（削除、上書き保存）で確認ダイアログを表示すること。
- 例外発生時にアプリが強制終了せず、ユーザーへ案内できること。
- 入力値検証ルールを全画面で統一すること。

### 受け入れ条件
- 大量データ読込時に操作不能にならない。
- 削除/上書き時に確認ダイアログが表示される。
- 例外発生時にエラーメッセージを表示し、操作継続可能。

## 8. 非機能要件
- アプリ形態: C# WinForms デスクトップアプリ
- データ永続化: CSV優先
- 開発方針: TDD（NUnit）
- 変更管理: `feature/* -> develop` のPR運用
